Checkpoint 2

What did we train?

Example response

The inputs were pet photographs. The labels were “cat” and “not cat,” derived from the file names. The model learned from a training portion of the images, while a separate validation portion was used to measure how well it handled examples it did not train on.

My fictional validation error rate was 0.024, or about 2.4%. That means roughly 2 or 3 of every 100 held-out images were classified incorrectly in this run. It does not guarantee the same performance on every image found online.

Training changes the model using labeled examples. Prediction uses the trained model to produce an output for a new input without changing the model.

Why this works: it translates a metric into plain language and does not overclaim what the number proves.

Inspect predictions

Image A · clear cat portrait

Before running: cat, with high confidence. Fictional output: cat, 0.99.

The result matched my prediction. The face, ears, and whiskers were large and unobstructed, so the image resembled a straightforward training example.

Image B · small dog under a blanket

Before running: dog, but uncertain. Fictional output: cat, 0.63.

The model disagreed with me and was less confident. Most of the animal was hidden, and the visible pointed ears may have resembled features associated with cats. This is a useful failure because it suggests that context and occlusion matter.

Image C · fox photographed outdoors

Before running: neither label is appropriate. Fictional output: not cat, 0.91.

The binary classifier still had to choose one of its two labels. “Not cat” is technically compatible with a fox, but the output does not mean the model recognized a fox. The test exposes how the available labels limit what a prediction can mean.

Why these work: each record separates the student’s prediction, the model’s evidence, and the interpretation.

Checkpoint 5

Compare the examples

Pet classification · ranData: labeled pet photographs. Input: one image. Output: cat or not-cat probability. Model: a pretrained convolutional image classifier adapted to this task.
Image segmentation · inspectedData: street-scene images with a category for each pixel. Input: one image. Output: a labeled region map. Model: a U-Net-style vision model.
Movie-review sentiment · inspectedData: IMDB review text with positive or negative labels. Input: a review. Output: sentiment prediction. Model: a pretrained language model adapted for classification.
Adult-income tabular model · ranData: rows of demographic and employment fields. Input: one row of mixed categories and numbers. Output: an income category. Model: a tabular neural network.
Movie recommendation · ranData: users’ movie ratings. Input: a user and movie pair. Output: a predicted rating. Model: collaborative filtering using learned user and movie factors.
Example explanation of held-out data

We hold out evaluation data because performance on the same examples used for training can be misleading. A validation set gives the model examples it did not learn from, so it is a better test of whether the learned pattern generalizes.
